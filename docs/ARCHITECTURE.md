# Архитектура Prompt Engineer in Your Pocket

## Обзор

Приложение построено на **Next.js 14 (App Router)** и совмещает SSR/SSG, серверные экшены и клиентские интерактивные фичи. Вся бизнес-логика сосредоточена в feature-модулях и API-роутах Next.js. Данные хранятся в PostgreSQL/SQLite через Prisma ORM, локальные предпочтения — в Zustand.

```
┌─────────────────────────┐
│   Клиент (React 18)     │
│  • App Router           │
│  • Zustand + ReactQuery │
│  • shadcn/ui, Tailwind  │
└────────────┬────────────┘
             │HTTP + fetch
┌────────────▼────────────┐
│ Next.js Route Handlers  │
│  • REST API (/api/*)    │
│  • NextAuth             │
│  • OpenAI wrapper       │
└────────────┬────────────┘
             │ Prisma ORM
┌────────────▼────────────┐
│      Database           │
│  SQLite (dev) / PG (prod)│
└─────────────────────────┘
```

## Слои

### 1. UI / Features
- `src/app/[locale]/*` — страницы и маршруты с локализацией через `next-intl`.
- `src/features/*` — feature-модули (онбординг, билдер, шаблоны, библиотека, настройки). Каждый модуль агрегирует компоненты, хуки и обращается к API через `apiClient`.
- `src/components/*` — дизайн-система: CircleCard, CategoryCard, PromptCard, модальные окна, утилитарные компоненты shadcn/ui.

### 2. Состояние
- **Zustand** (`src/store`) хранит локальные предпочтения: прогресс онбординга, состояние модалок. Для онбординга используется `persist` middleware (localStorage).
- **React Query** отвечает за данные с сервера (`/api/tools`, `/api/templates`, `/api/prompts` и т.д.), кеширование и инвалидацию.

### 3. Серверная логика
- **Next.js Route Handlers** (`src/app/api`) реализуют REST-контракты:
  - `/api/tools`, `/api/categories` — справочники.
  - `/api/templates` (+ CRUD, import/export) — управление шаблонами.
  - `/api/generate` — генерация промпта (валидация Zod, вызов `generatePrompt`).
  - `/api/prompts` — библиотека сохранённых промптов.
  - `/api/settings/*` — пользовательские настройки и OpenAI API-ключ.
- **NextAuth** (`src/auth.ts`) — Email provider + Credentials demo. Сессии хранятся в БД.

### 4. Доменные сервисы (`src/lib`)
- `prompt-engine.ts` — связывает шаблоны, стратегию инструмента и OpenAI. Формирует итоговый текст и мета-информацию.
- `tool-strategies.ts` — пресеты системных промптов и fallback-тексты для популярных инструментов.
- `templates.ts` — рендеринг шаблонов, сериализация/десериализация переменных.
- `openai-client.ts` — безопасный вызов OpenAI (rate limit, fallback при отсутствии ключа).
- `api-client.ts` — thin wrapper над `fetch` на клиенте.
- `rate-limit.ts` — in-memory rate limit (конфигурируется через env).

### 5. Данные
- Prisma schema (`prisma/schema.prisma`) содержит модели пользователей, инструментов, категорий, шаблонов и генераций.
- `prisma/seed.ts` заполняет инструментами, категориями и 10+ шаблонов по направлениям (маркетинг, разработка, обучение и т.д.).

## Поток «Онбординг → Генерация → Сохранение»

1. Пользователь выбирает инструменты, категорию и вводит бриф (Zustand store).
2. После завершения онбординга происходит редирект на `/builder`.
3. Конструктор подтягивает инструменты/категории/шаблоны из API (React Query).
4. По нажатию «Сгенерировать промпт» отправляется POST `/api/generate`.
5. `generatePrompt` подбирает шаблон, рендерит тело и (опционально) вызывает OpenAI. Возвращается готовый текст + мета.
6. Пользователь может скопировать, открыть модал отправки или сохранить промпт.
7. Сохранение вызывает POST `/api/prompts`, данные попадают в таблицу `PromptGeneration`. Библиотека автоматически рефрешится.

## Локализация и темы

- `next-intl` управляет маршрутами (`/ru/...`, `/en/...`). Файлы переводов лежат в `src/i18n/locales`.
- Тема (`light`/`dark`) переключается через `next-themes` и хранится в настройках пользователя (POST `/api/settings/preferences`).

## Тестирование

- **Vitest** (`src/lib/__tests__`) покрывает утилиты шаблонов и стратегии инструментов.
- **Playwright** (`tests/e2e/onboarding.spec.ts`) проверяет основной пользовательский сценарий.
- GitHub Actions запускает lint → typecheck → test → build для каждого PR.

## Производительность и безопасность

- API-ключи не уходят на клиент: `/api/settings/openai` хэширует ключи.
- Rate limit на генерацию предотвращает злоупотребления.
- Все маршруты (кроме публичных справочников) требуют аутентификацию через NextAuth.
- Используются легковесные анимации Framer Motion и ленивые запросы через React Query.
